# Evoker iOS — architecture plan

Written 2026-10-11 as the guide for the native rewrite. The reference implementation is `../../Evoker Web/`
(vanilla ES modules; its `docs/design/*.md` are binding for rules and numbers). This document says how each
web system maps to Swift, what is shared, who owns what, and what the risks are. Status of each item is kept in
`../README.md`.

## 1. Goals and non-goals

- A fully native iOS 17+ app (iPhone first): SwiftUI for every menu / deck screen, SpriteKit for the battle.
- The game logic is a separate Swift package, `EvokerCore`, with no UIKit dependency, unit-tested, and holding
  **golden tests** that replay outcomes recorded from the web engine (same seed → same event log).
- Art and sound live behind one asset catalog (`GameAssets/` + the `AssetCatalog` protocol) so they can be swapped.
- Out of scope: multiplayer (as requested); the first-session tutorial *script* (the ranger overlay, the opening
  cinematic and scripted fight of `Evoker Web/src/ui/tutorial/`) is deferred to a later round — its *data*
  (tutorial bosses of quests 1–10, soul-card drops, quest-based feature unlocks, the name prompt at the first
  Arena visit) is in `EvokerCore` and the game plays the 1.7.0 early game without the hand-holding overlay.

## 3. How the web systems map to Swift

| Web (Evoker Web/src) | Swift | Notes |
|---|---|---|
| `core/rng.js` mulberry32 | `Core/Mulberry32.swift` (`final class`, reference semantics like the JS closure) | UInt32 wrapping arithmetic (`&+`, `&*`), `Double(x) / 4294967296` |
| JS `Math.round/floor/imul`, `>>> 0`, `\|0` | `Core/JSMath.swift` | `jsRound` = floor(x + 0.5) semantics (JS rounds .5 up, Swift `rounded()` rounds away from zero) |
| `core/constants.js` | `Core/Constants.swift` (`enum Constants` namespace of static lets) | every tuning table, same names |
| `core/stats.js` | `Core/Stats.swift` (`struct Stats: StatsProviding`) | memoised per (cardId, stat, stage, level); percent abilities keep 1 decimal |
| `core/cards-db.js` | `Core/CardsDb.swift` (`final class CardsDb`) | catalog order preserved (goldens depend on it) |
| `core/abilities.js` | `Core/Abilities.swift` | validate, `abilityForStage`, `buffsForStage`, `renderAbilityText`, `effectDirs` |
| `engine/*` | `Engine/*` | literal port: internal `final class` card/player state (identity semantics: `===`, `damagedBy` sets of `ObjectIdentifier`), 28-entry phase list, event loop, `kill` after the phases |
| `engine` event log (plain objects) | `enum BattleEvent` (Codable, JSON shape identical to the web: `t` discriminator) | goldens compare canonical JSON of the whole log |
| `game/*` pure functions `(state, deps, now, args) -> {state, ...info}` | `enum Game.X { static func f(state:deps:now:args:) throws -> (state: GameState, info) }` | `now` is `Int64` ms epoch; `throws` replaces thrown `Error`s; info is a typed struct per function |
| `state.takeRng` / `mixSeed` | `GameState.takeRng(deps)` / `Seeds.mixSeed` | same hash, same step counter → the same roll sequence as the web |
| save object (`evoker.save.v1`) | `GameState: Codable` with the same keys | a web export can be imported on iOS and vice versa |
| `ui/store.js` | `App/AppModel` (`@MainActor final class GameStore: ObservableObject`) + `Game/StoreHelpers.swift` (pure parts: `shiftClocks`, `parseSave`, `seedFromNow`) | `update { state, deps, now in … }` autosaves and publishes |
| `ui/router.js` screen stack | `App/Router.swift`: `NavigationStack(path:)` over a `Route` enum; `goTop` resets the path | one-shot params (boss intro) are consumed by the screen |
| `ui/screens/*.js` | `Screens/*.swift` SwiftUI views, one per screen id | layout tokens from `css/tokens.css` in `Theme.swift` |
| `ui/components/*.js` | `Components/*.swift` | nine-slice frames = `Image.resizable(capInsets:)` on the original sprites |
| `ui/components/drag-drop.js` | `Components/DragDrop.swift` (`DragGesture` + a drop-target registry via `PreferenceKey`) | deck editing, pre-battle, training, fusion |
| `ui/battle/timeline.js`, `model.js` | `Playback/Timeline.swift`, `Playback/BoardModel.swift` (in EvokerCore, pure, tested) | the SpriteKit scene only *plays* steps |
| `ui/battle-player.js`, `battle/fx.js`, `battle/assets.js` | `Battle/BattleScene.swift`, `Battle/BattlePlayer.swift`, `Battle/BattleFX.swift`, `Battle/BattleSounds.swift` | `SKAction` sequences per step; skip = jump to `BoardModel.final` |
| `ui/audio.js` | `Audio/AudioPlayer.swift` (AVAudioPlayer pool, music crossfade) | same sound names (file stems in `GameAssets/sfx`) |
| `ui/card-view.js` | `Components/CardViewModel.swift` | `cardView / defView / battleView / artFor` |
| `localStorage` | `Persistence/FileSaveStore.swift` (JSON file in Application Support, atomic write, previous copy kept) | `SaveStore` protocol lives in EvokerCore |
| `assets/` folders | `GameAssets/` + `Assets/AssetCatalog.swift` | one protocol: `image(_:)`, `cardArt(id:stage:)`, `sound(_:)`, `font(_:)`, `animation(_:)` |
| `tools/build-cards.js` (data pipeline) | not ported: the iOS package consumes the *built* `cards.json` (`Tools/sync-data.mjs`) | data is authored in the web repo |
| tutorial script (`ui/tutorial/*`) | deferred (see §1); `TutorialRecord` is in the save model | new iOS games get `r3 = {intro: true, done: true, named: false}` so unlocks follow quest wins and the name is asked at the first Arena visit |

### 3.1 Numeric semantics (the golden tests depend on these)

- The engine works in `Double` internally exactly like JS and converts to `Int` only when emitting events
  (every emitted value is integral in practice). Stats: `attack`/`hp` are `Int`, the ability value is `Double`
  (percent cards carry one decimal).
- `jsRound(x)` is `floor(x + 0.5)`; `jsFloor` is `floor`; `jsTrunc` is `Int(x)` (`| 0`); `Math.imul` is `&*` on
  `UInt32`/`Int32`; `>>> 0` is `UInt32(truncatingIfNeeded:)`.
- Integer division never replaces `/`: port `Math.round(a / b)` as `jsRound(Double(a) / Double(b))`.
- Iteration order: JS arrays and `Map` keep insertion order — Swift arrays / `KeyValuePairs` / sorted keys. Never
  iterate a Swift `Dictionary` where the JS iterated an object whose order mattered (`Object.entries` over
  integer-like keys is ascending: sort the keys).
- `Array.sort` in JS is stable; Swift's `sort` is stable too (documented since Swift 5), but comparators must
  return exactly the same ordering (ties!).
- `String.localeCompare` (name sorts) → `compare(_:options:[.caseInsensitive?])`: the web uses the default locale
  compare on card names (ASCII, plus "Will-o'-the-Wisp"); use `a < b` on the lower-cased names unless a golden says
  otherwise.
- Dates: `utcDay(now)` = `YYYY-MM-DD` of the UTC day; `utcDayStart` = `floor(now / 86_400_000) × 86_400_000`.

## 6. Battle presentation (SpriteKit)

- `BattleScene` uses a 720-unit-wide logical coordinate system (the web stage is 720 × 1280); the height follows
  the device (`scaleMode = .resizeFill`, size set from the view). Bands pin to the top/bottom safe areas, the two
  rows sit around the vertical centre (opponent row above, own row ~135 units below, slots 65 × 2.25 units apart
  like `comp_fight_layout`).
- Input: `BattlePresentation { events, result, attacker/defender views, rewards, levelUps, cardLevelUps, mode }`.
  The scene builds `Timeline.fromEvents(events)` and plays steps sequentially with `SKAction.run`/`wait`;
  `speed` scales durations; `skip()` removes all actions and applies `BoardModel.final(events)`.
- Effects map 1:1 to `battle-player.js`'s table (wind-up glow, bullet along the card's arrow through empty slots
  to the HP bar, impact burst + shake + red "−N", blocked shield, reflect shockwave, heal sparkles, buff arrows,
  dazed/suspended/indestructible overlays, death shatter into two halves, revive flare, tribe-bonus emblem, round
  counter, lethal finale with starburst, Victory/Defeat/Draw banner). Sounds via `BattleSounds` (same stems and
  seeded variant picker).
- After the fight: the SwiftUI `BattleResultView` overlay (loot, card XP bars, level-ups, Continue) then `onDone`.

## 7. Persistence

- `SaveStore` (EvokerCore): `load() throws -> GameState?`, `save(_:) throws`, `delete() throws`,
  `exportJSON() throws -> Data`, `importJSON(_:) throws -> GameState`.
- `FileSaveStore`: `Application Support/Evoker/evoker.save.v1.json`, atomic writes, `.bak` of the previous save,
  `JSONDecoder` lenient migration (`GameState.migrated(from:now:)` mirrors `state.js migrate`, then `pruneRemoved`).
- `GameStore.update` autosaves synchronously on a serial queue after every change (saves are ~50–100 KB).
- Export/import: share sheet (`.json`) and `fileImporter`, same format as the web's Options screen.

## 8. Asset pipeline

- `Tools/build-assets.mjs` copies `Evoker Web/assets/{cards,ui,bg,orig/*}` into `GameAssets/<group>/` keeping file
  names (card art `Adept+.jpg` etc.), rejects duplicate stems inside a group, writes `manifest.json`
  (`{ cards: {id: {stage: file}}, ui: [stems], sfx: [stems], fonts: {role: file}, bg, map, minions, portraits,
  animations }`). The app bundle keeps the folder (folder reference) so paths are stable.
- `BundleAssetCatalog` resolves through the manifest with an `NSCache` of `UIImage`/`SKTexture`; a missing card art
  falls back to the stage-0 art, then to a generated placeholder with the tribe colour (`card-placeholder.svg`
  is rendered as a vector `UIImage` is not possible without a library → a flat `UIImage` drawn with Core Graphics).
- Fonts (`proximanova-light.ttf`, `proximanova-sbold.ttf`, `07713_CGTimesBold.ttf`, `Roboto-Bold.ttf`) are
  registered at launch with `CTFontManagerRegisterFontsForURL`; no `UIAppFonts` plist key is needed.
- `Tools/make-icon.py` renders the 1024 px AppIcon from `assets/orig/ui/evoker.png` on the key-art background.

## 9. Testing

- `EvokerCoreTests` (XCTest; runs with `swift test` on macOS/Linux/Windows and in Xcode):
  - `JSMathTests`, `RngTests` (first 20 values of seeds 1, 42, 2^31), `StatsTests` (wiki checkpoints),
    `AbilitiesTests` (validation of every entry, `buffsForStage`), `EngineTests` (ported cases of
    `tests/battle.test.js`), `TimelineTests`, `GameTests` per module.
  - Golden tests (`Golden/*.json`, produced by `Tools/gen-goldens.mjs` from the web code — never edited by hand):
    `battles-original.json` (the 64 client unit tests through the web engine: full event logs), `battles-cards.json`
    (one fight per card: the card in the middle slot against a fixed row, like the Card Lab), `battles-random.json`
    (40 seeded real-catalog fights), `stats.json` (every card × stage × 3 levels + xp/sell/price tables),
    `game-*.json` (sequences of game function calls with the state after each call).
  - Comparison: both sides serialise to canonical JSON (sorted keys, integers without a fraction) and the test
    prints the first differing path.
- The app target has no unit tests of its own in round 1 (no Mac available while this was written); the
  reviewer agent checks the UI code for API correctness instead, and `README.md` lists the manual smoke tour.

## 10. Risks and mitigations

| Risk | Mitigation |
|---|---|
| No Mac/Xcode on the machine that writes this: the app target cannot be compiled here | EvokerCore is compiled and tested with a Swift toolchain on Windows (if one could be installed) or at least type-checked; the app code is kept to well-known iOS 17 APIs, reviewed twice, and a GitHub Actions workflow (`.github/workflows/ios.yml`, opt-in) can build it on a macOS runner |
| Hand-written `project.pbxproj` | objectVersion 77 synchronized-folder format copied from Xcode 16's template; `Tools/check-pbxproj.mjs` verifies ids and references; `project.yml` (XcodeGen) regenerates the project if Xcode rejects it |
| Engine divergence (rounding, order of events, identity semantics) | literal port with `Double` internals and `jsRound`; goldens over every card's ability; the engine agent diff-reviews handler by handler |
| RNG consumption order in the game layer (`takeRng` steps) | game goldens replay whole sequences and compare states after every call |
| JSON save compatibility | `GameState` keys = web keys; lenient decoding; `game-migrate.json` golden imports a real web save |
| Asset volume (~180 MB of art and sound) | the bundle is a sideload build; `build-assets.mjs` can downscale later; the catalog is swappable |
| SwiftUI drag & drop between a scrolling slider and 5 slots | own `DragGesture`-based coordinator (`Components/DragDrop.swift`) with preference-key geometry, as the web uses pointer events rather than HTML5 DnD |
| Swift 6 strict concurrency noise in Xcode 26 | targets use Swift 5 language mode (`SWIFT_VERSION = 5.0`, `swift-tools-version: 5.9`); `@MainActor` on the store and views |
